# 薬液調合ノート(オフライン対応PWA)

農薬タンクミックスの薬量・水量計算と防除記録アプリ。
一度開けば圏外の圃場でも動作します。データは各端末内に保存されます。

## 画面構成(v8.57〜)

| タブ | 中身 |
|---|---|
| 🧮 薬剤登録・希釈計算 | 「🧮 調合電卓」= タンク1杯分の計算 ／ 「🧪 薬剤・プリセット」= 薬剤マスタと調合プリセット |
| 🚁 作業予定・進捗確認 | 「📋 作業一覧」= その日の作業と実績 ／ 「🚦 進捗地図」= 散布の進み具合を色で見る |
| 🗺 圃場登録・圃場一覧 | 「🗺 地図」= 圃場を囲んで位置を登録 ／ 「📋 圃場一覧」= 圃場マスタ(登録・編集・削除) |
| ⚙ 設定 | 単位・作物マスタ・送信・共有・農薬データなど |

v8.56までは独立した「📋 データベース」タブに圃場と薬剤がまとまっていました。
地図で見ている圃場を直すのに別のタブへ移る必要があり、行き来が多かったため
それぞれ関係するタブへ入れています。

## GitHub Pagesでの公開手順

### 1. リポジトリを作成
GitHubで新規リポジトリを作成(例: `tankmix-note`)。Public にする
(Privateの場合、Pagesは有料プランが必要)。

### 2. ファイルをアップロード
このフォルダの中身(8ファイル)をすべてリポジトリの**ルート直下**に置く。

ブラウザから: リポジトリ画面 → 「Add file」→「Upload files」→ 8ファイルをドラッグ&ドロップ → Commit

またはコマンドで(WSLから):
```bash
cd site
git init
git add .
git commit -m "薬液調合ノート 初版"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/tankmix-note.git
git push -u origin main
```

### 3. Pagesを有効化
リポジトリの Settings → Pages →
- Source: 「Deploy from a branch」
- Branch: 「main」/「/ (root)」 → Save

1〜2分後、`https://<ユーザー名>.github.io/tankmix-note/` で公開されます。

### 4. スマホのホーム画面に追加
公開URLをスマホで開いて:
- **iPhone**: Safariで開く → 共有ボタン → 「ホーム画面に追加」
- **Android**: Chromeで開く → メニュー(⋮) → 「ホーム画面に追加」または「アプリをインストール」

以後はアイコンから起動でき、**圏外でも動作**します。

## 更新のしかた

1. 変更したファイル(通常は app.js や index.html)をリポジトリに上書きプッシュ
2. **sw.js の1行目 `CACHE_VERSION` の数字を上げる**(例: tankmix-v1 → tankmix-v2)
   ※これを忘れると各端末に古いキャッシュが残り続けます
3. 各端末では、オンライン状態で一度開き直すと新版に切り替わります

### Code.gs を変えたら受信側のテストも流す

スプレッドシート側の受信処理(圃場・作業の保存、差分取得、進捗の読み出し、
合言葉の照合、数式インジェクション対策)を Node 上で確かめます。
Googleに接続せず、スプレッドシートだけを張りぼてに差し替えて、
配布する Code.gs そのものを動かします。

```
node tools/gastest.cjs
```

手元のブラウザで送信まで通して確かめたいときは、確認用の受信口を立てられます。

```
node tools/fakegas.cjs
```

`http://127.0.0.1:8932/exec` を設定タブの「送信先URL」に入れると、Googleに
何も送らずに動作を確認できます。データはメモリ上だけで、終了すると消えます。
※アプリ側のCSP(index.html)は送信先を Apps Script に限っているため、
　この確認をするには index.html の `connect-src` を一時的に緩める必要があります。
　**緩めたまま公開しないでください。**

### 変更したら自己テストを流す

app.js の計算部分(面積・薬液量・タンク補給・アグリノートの
まとめ方・薬剤検索など)を Node で直接動かして確かめられます。

```
node tools/selftest.cjs
```

配布する app.js そのものを読み込んで検証するので、テストのために
本体を分割する必要はありません。`app.js` と `sw.js` の版数が
そろっているかもここで確認します。
プッシュ前に流して、全項目が成功することを確かめてください。

## Googleスプレッドシート連携(記録の自動集約)

各端末の記録を1枚のスプレッドシートに自動で集める機能です。
圏外で保存した記録は端末に貯まり、電波が戻ると自動送信されます。

### 設置手順(最初に1回だけ)

1. **Googleスプレッドシートを新規作成**(名前は自由。例:「防除記録」)
2. メニュー **拡張機能 → Apps Script** を開く
3. 最初から入っているコードを全部消して、同梱の **Code.gs** の内容を貼り付けて保存
4. 右上 **デプロイ → 新しいデプロイ** → 歯車アイコンで種類 **ウェブアプリ** を選択
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員** ←ここが重要
5. **デプロイ** を押す(初回は「アクセスを承認」→自分のアカウントを選択
   →「詳細」→「(プロジェクト名)に移動」→ 許可、と進む)
6. 表示された **ウェブアプリのURL**(`https://script.google.com/macros/s/…/exec`)をコピー

### 各スマホでの設定(1台につき1回)

1. アプリの **記録タブ →「設定」** を開く
2. **送信先URL** にコピーしたURLを貼り付け
3. **記録者名** に名前を入力(シートの「記録者」列に入ります)
4. **接続テスト** を押して「✅接続OK」が出れば完了

以後、「記録に保存」するたびに自動でシートに1行ずつ追加されます。
記録の右上に「✓送信済」/「未送信」バッジが表示されます。

### スクリプトを更新した場合

Code.gsを修正したときは、デプロイ → **デプロイを管理** → 鉛筆アイコン →
バージョン「**新バージョン**」→ デプロイ、で反映します(URLは変わりません)。

## 農薬データの取り込み

農薬の登録番号・名称・成分での検索に使うデータ(`chemdb.json`)は、アプリに
同梱していません。FAMIC(農林水産消費安全技術センター)の利用規約が無断の
改変・転載を認めていないため、加工した派生データを公開リポジトリで再配布しない
方針にしています。各自でデータを用意し、自分のGoogleドライブと自分のApps Script
経由で端末に取り込んでください。

先に「Googleスプレッドシート連携」の設置と、各端末の送信先URL・共有パスワードの
設定を済ませておいてください。取り込みはその通信路をそのまま使います。

1. **データを作る**
   ```
   python tools/update_chemdb.py
   ```
   リポジトリ直下に `chemdb.json` ができます。
   **これはリポジトリにコミットしないでください**(`.gitignore` に入れてあります)。
2. **Googleドライブにアップロードする**
   できた `chemdb.json` を自分のGoogleドライブにアップロードし、そのファイルを
   開いたときのURL
   `https://drive.google.com/file/d/【ここがファイルID】/view`
   からファイルIDを控えます。
3. **Apps Script にファイルIDを設定する**
   Apps Script の左メニュー「プロジェクトの設定」(歯車)→「スクリプト プロパティ」
   → プロパティ名 `CHEMDB_FILE_ID` ／ 値 手順2のファイルID → 保存。
   そのあと デプロイ → デプロイを管理 → 鉛筆 → バージョン「新バージョン」→ デプロイ。
   ※IDを設定しない場合はドライブ内の「chemdb.json」という名前のファイルを探しますが、
   同名ファイルが複数あると別のものを掴むので、IDの設定を推奨します。
4. **各端末で取り込む**
   アプリの **設定タブ →「農薬データ」→「⬇ 農薬データを取り込む」**。
   約940KBを分割して受け取るので、進捗が「1/4 パート」のように表示されます。

取り込んだデータは端末内(IndexedDB)に保存されます。一度取り込めば**圏外でも検索
できます**。データを更新したいときは、手順1〜2でドライブのファイルを差し替えてから
各端末で取り込み直してください(同じファイルIDのまま中身を更新すれば手順3は不要です)。

### 更新は必須ではない

取り込んだデータが古くなっても、アプリが動かなくなるわけではありません。
新規登録・失効などで実態と少しずつずれていくだけです。このアプリの検索は
あくまで登録番号・名称の確認補助であり、実際の使用可否は各薬剤のラベル・
容器の表示を優先してください(下の「注意」欄も参照)。

- 新しい薬剤をよく調べる運用なら、月1回程度の更新が目安(FAMICの原則更新頻度)
- 既知の薬剤の確認が主な用途なら、更新しなくても実用上困りません

## 圃場を囲むときの「ねじれ」(v8.52〜)

線が交差した形（蝶ネクタイ形）で登録しようとすると警告が出ます。ねじれた形は
面積が実際よりはるかに小さく計算される（交点が真ん中なら 0a）ためです。

**原因は回り方ではありません。** 時計回りでも反時計回りでも結果は同じで、
自己テストでも一致することを確認しています。交差するのは、**外周をたどる順に
打っていない**ときです。たとえば `左 → 右上 → 左下 → 右` の順で打つと、
2本目と4本目の線が交差します。正しくは `左 → 右上 → 右 → 左下` です。

打ち直さなくても、警告の下に出る **「🔀 並び順を直す」** で直せます。
頂点の座標は1つも動かさず、重心から見た角度の順に並べ替えるだけです。
押したあと「↩ 1つ戻す」で元に戻せます。

⚠ 大きくへこんだ（凹んだ）形の圃場では、角度順が意図した形と変わることがあります。
そのため自動では適用せず、ボタンを押したときだけ実行します。結果を見てから登録してください。

## 全画面のまま圃場を囲める(v8.52〜)

「⛶」で全画面にしたまま作図できます。全画面のときの操作欄は**画面下の1行**だけです
（v8.54〜。それ以前は画面の半分近くを占めていました）。

```
4点 ／ 19.98 a ⚠交差 | 🔀 並び順 | ✏ ON | ↩ | 🗑 | ✕ |        ✓ 登録
```

- **✏ ON / 🔒 OFF** … 地図をタップして頂点を増やすかどうか
- **↩** … 1つ戻す ／ **🗑** … 全消し ／ **✕** … 作図をやめる
- **🔀 並び順** … 線が交差しているときだけ出ます
- **✓ 登録** … 圃場名・作物名・地区の入力がポップアップで開きます

圃場名などの入力欄は、地図を見ている間は表示されません。

### 続けて囲める(v8.55〜)

全画面で新しい圃場を登録すると、**そのまま次の圃場を囲める状態に戻ります**。
全画面を抜けて「✏ 圃場を囲む」を押し直す必要はありません。1行バーが「0点 ／ 0 a」に
戻ったら、次の圃場を囲めます。やめるときは1行バーの「✕」を押してください。

登録済みの圃場をタップして編集していたときは続けません(これまでどおり1枚で終わります)。
編集は1枚ずつ終わる作業で、続けて作図に入ると意図しない圃場ができるためです。

### 地図の回転について

**回転・向きの変更はできません。対応しない方針です（2026-08-26 決定）。**

Leaflet 本体に回転機能がなく、対応するには第三者プラグイン（leaflet-rotate）の
同梱が必要になります。しかしこれは **GPL-3.0** で、同梱するとアプリ全体を
GPL-3.0 で配布する義務が生じ、このリポジトリの `LICENSE`（All rights reserved）と
両立しません。調査内容と判定は `THIRD-PARTY-LICENSES.md` の
「検討して見送ったもの」に残してあります。

## 進捗マップ(v8.51〜 / v8.55で作業タブへ統合)

散布の進み具合をチームで共有する地図です。**🚁作業** タブを開き、作業日の下の
**「📋 作業一覧 ／ 🚦 進捗地図」** で切り替えます(v8.54までは独立した🚦進捗タブでした。
今日の作業を見るのに2つのタブを行き来することになり、現場で見づらかったため統合しました)。
圃場の位置を作図・編集する **🗺地図** タブとは別で、進捗地図に編集の操作はありません
(散布中に地図を触って、囲んだ形を壊す事故を避けるため)。

- 作業日・圃場数・合計面積・合計薬液量は、作業一覧と進捗地図のどちらでも共通で出ます
- 選んだ表示(一覧/地図)は端末に残ります
- 圃場の色は **緑=実施済** ／ **赤=未実施** ／ **灰=その日の作業に入っていない圃場(対象外)**
  の3つだけです(v8.56〜)。調合済は赤(未実施)に、この端末から未送信の実績は緑(実施済)に
  まとめています。未送信の件数は地図の上に文字で出ます
- v8.54までは 黄=調合済 / 橙=未送信 を別の色にしていました。直射日光下では
  赤とも緑とも読めなかったためやめています
- **「⊙ 今日の圃場へ」**でその日の圃場が入る位置へ寄せ直せます(v8.56〜)。
  最初に開いたときも、登録済みの全圃場ではなく**その日の圃場**が入るように寄せます
- その日の作業に入っているのに地図で囲まれていない圃場があると
  **「地図に出せない圃場 n件(位置未登録)」**と出ます。地図タブで囲むと出るようになります
- 上部に `実績 n / m 圃場` と実績面積を表示します
- 表示するのは**作業タブで選んでいる日の作業**です。期間は選べません
- **登録済みの圃場はすべて表示されます。** その日に作業がない圃場は灰色（対象外）です。
  対象だけを見たいときは「◉ 対象だけ / ○ 全圃場」で切り替えてください（既定は全圃場）
- **進捗地図を開いている間は45秒ごとに自動で取り直します**(v8.55〜)。画面が裏に回っている間と、
  作業一覧を見ている間は取りに行きません。表に戻ってきたときは即座に1回取り直します。
  「🔄 最新を取得」を押せばその場でも取り直せます。
  最後に取れた内容は端末に残り、圏外では「最終取得 8/26 12:42」のように
  いつ時点のものかを添えて表示します

使うには、各端末で「送信先URL」と「チームコード」の設定が要ります。
**同時に散布する班どうしは、同じチームコードにしてください。**
別のチームコードにすると互いの進捗が見えません(班の区別は記録者名で行います)。

### 圃場名を連番で付け直す(v8.62〜)

🗺地図タブ → 「📋 圃場一覧」→ 地区の見出しの「🔢 連番」。
その地区の圃場名を「嘉島1」「嘉島2」…の形で一括で付け直します。

- 丸数字(①⑧⑮)も普通の数字として読みます(NFKC 正規化)。
  「嘉島①」と「嘉島52」が混ざっていても、番号順に並べ直してから振ります
- 番号の入っていない名前は末尾に回ります
- 名前の頭と開始番号を変えられ、実行前に「前 → 後」の一覧が出ます
- **戻せません。** 確認画面で件数と例を出してから実行します
- 変わるのは名前だけです。囲んだ形・面積・作物・過去の作業の記録はそのままで、
  作業側に控えている圃場名も同時に追従します
- 付け直した内容は自動で共有へ送られます(圃場の自動送信と同じ経路)

### 自動取得の間隔と Apps Script の上限(v8.58〜)

設定タブの「送信・共有」②で間隔を選べます(自動で取らない / 10秒 / 15秒 / 30秒 / 1分 / 3分、既定30秒)。
作業タブ・地図タブを開いている間だけ回り、画面が裏に回っている間は止まります。

Apps Script の公式の上限(公式ドキュメントを 2026-08-26 に確認):

| 項目 | 個人(gmail.com) | Workspace |
|---|---|---|
| 1回の実行時間(Script runtime) | 6分 | 6分 |
| 同時実行(Simultaneous executions) | 30 / ユーザー | 30 / ユーザー |
| トリガーの合計実行時間(Triggers total runtime) | 90分 / 日 | 6時間 / 日 |
| UrlFetch の呼び出し | 20,000 / 日 | 100,000 / 日 |

注意点が2つあります。

- **「90分/日・6時間/日」はトリガーの合計実行時間**であって、このアプリが使う
  ウェブアプリ(doGet / doPost)の呼び出しには当たりません。このアプリはトリガーを使っていません
- **ウェブアプリの1日あたりの呼び出し回数の上限は、公式の表に載っていません。**
  載っていないことと「無制限」は別です。**このアプリでは実測していません**
- UrlFetch は「スクリプトが外へ取りに行く回数」です。このアプリの送受信はこれには入りません

出典: [Quotas for Google Services](https://developers.google.com/apps-script/guides/services/quotas)

### 作業予定の共有(v8.58〜)

作業リストに圃場を入れた・薬剤を当てた・外した時点で自動送信され、
受け取る側は**作業タブを開いたとき・作業日を切り替えたとき**に取りに行きます(60秒に1回まで)。

v8.57までは作業は**送るだけ**でした。サーバー側にも進捗マップ用の要約
(状態・実績量・薬剤名の文字列)しか置いていなかったため、受け取っても
希釈倍率や量を戻せませんでした。v8.58 で「作業」シートに列を7つ足しています
(作物 / 面積a / 薬剤JSON / 総量L / 水量mL / 備考 / 並び順)。

- 他の端末から受け取った作業には「👥 記録者名」が付きます
- 「防除記録」シートへの台帳の送信は、**その作業をした端末の役目**としています。
  受け取っただけの端末でも未送信扱いにすると、全員の画面に同じ件数が出て
  誰が送るべきか分からなくなるためです。こちらで「散布済」を押し直せばこの端末からも残ります
- **並び順だけを入れ替えたときは送信されません。** 中身が変わらないためで、
  相手側の並びは前回送った時点のままになります(**未解決**)
- 古い Code.gs のままだと作業は取り込まれません。応答に `plan: true` の印が
  ないときは見送ります(見送らないと、手元の薬剤の中身が空で上書きされる)

### 圃場と薬剤の共有は自動(圃場 v8.55〜 / 薬剤 v8.57〜)

圃場を登録・編集・削除したとき、薬剤を登録・編集・削除したときは、
**その場で自動送信**されます。受け取る側は、アプリを開いたときと地図タブを
開いたときに自動で取りに行きます(60秒に1回まで)。

v8.54までは設定タブの「🔁 圃場を同期」を**両方の端末で押す**必要があり、押し忘れると
「作図したのに他の端末に出ない」が起きていました。

- 続けて何枚登録しても送信は1回にまとまります(1.5秒待ってから送るため)
- 圏外のときは未送信のまま残ります。電波が戻ってから設定タブの
  「🔁 今すぐ同期する」で送り直せます
- **チームコードは大文字小文字を区別します。** `Kajima` と `kajima` は別チーム扱いです
- 薬剤のIDは**薬剤名を正規化した文字列**です。別の端末で同じ薬剤を登録しても
  1件にまとまります。名前を変えると別の薬剤として扱われます

実績を保存したとき、および「散布済」チェックを入れ外ししたときは、進捗ぶんがその場で
自動でスプレッドシートへ送られます。他の端末は45秒ごとの自動取得でそれを受け取るので、
チェックを入れてから相手の地図の色が変わるまでの遅れは、通常45秒以内です
(電波状況によります。未計測)。圏外だったときは未送信のまま残るので、電波が戻ってから
設定タブの「🚦 進捗を送信」で送り直せます。

進捗地図に `取得できません(invalid payload)` と出るときは、スプレッドシート側の
Code.gs が古い版のままです。最新の Code.gs を貼り直し、「新バージョン」でデプロイし直して
ください(v8.55からは、この案内が画面にそのまま出ます)。

### 散布済チェック(v8.53〜)

作業タブの各圃場の左に **「散布済」チェック** があります。これが進捗マップの色の
入り口です。

- **チェックを入れる** → 実績済（緑）。散布量は入れなくてかまいません
- **チェックを外す** → 未実施に戻り、色も戻ります。実散布量・報告日も消えます
- 外したとき、スプレッドシートの「防除記録」も状態が **『調合済』に戻り**、
  実散布量と報告日が消えます。**行は消しません**（調合した事実は残るため）

散布量まで細かく記録したいときは、これまでどおり「🚁 実績入力」を使ってください。
どちらも同じ「実績」として扱われます。

### 投下量から実績を一括入力(v8.53〜)

「⚙ 今日の準備」の投下量（L/10a）の下に **「✓ 投下量から実績を一括入力」** があります。

撒きながらチェックだけ入れていき、最後にこのボタンを押すと、
**散布済にした圃場のうち実散布量がまだ空のもの**に `面積 ÷ 10 × 投下量` が入ります。

- 手で入れた実散布量は**上書きしません**
- チェックしていない圃場は対象外です（撒いていない圃場に実績が入らないように）
- 面積が入っていない圃場は対象外です

### 設定タブの「送信・共有」の中身(v8.57〜)

ボタンが6つ並んでいてどれを押せばよいか分からなかったので、4つの段に分けました。

| 段 | 中身 |
|---|---|
| ① つなぎ先 | 送信先URL・記録者名・チームコード・共有パスワード・接続テスト |
| ② データ共有(圃場・薬剤) | 「🔁 今すぐ同期する」。普段は自動なので、圏外の送り直し用 |
| ③ 作業データの送信 | 「🚦 進捗を送り直す」。これも普段は自動 |
| ④ 古い方式 | 「☁↑ 端末→共有へ保存 / ☁↓ 共有→端末へ読込」(畳んである) |

④の2つは、チームのデータを**丸ごと置き換える**方式です。誰かが保存すると、
他の人がその間に足した圃場や実績が消えます。また1つのセルに全部を詰めるので、
圃場が増えると「大きすぎます」で保存できなくなります。②はこのどちらも起きません。
**古い版の端末から移すとき以外は④を使わないでください。**

### スプレッドシート側の準備

Code.gs を最新の内容に差し替えて、**デプロイ → デプロイを管理 → 鉛筆 →
バージョン「新バージョン」→ デプロイ** してください(URLは変わりません)。
次の受信時に「圃場マスタ」「作業」「薬剤マスタ」シートが自動で作られます。
既にある「作業」シートには、v8.58 で列が7つ末尾に追加されます(既存の列は動きません)。
既存の「防除記録」シートはそのまま残り、書き込まれる内容も変わりません。

## 注意

- 記録・プリセットは**各端末のブラウザ内**(localStorage)に保存されます。
  端末間の同期はありません。集約したい場合は各自CSV出力してください。
- ブラウザのデータ消去(履歴削除で「サイトデータ」を含めた場合)を行うと
  記録も消えます。大事な記録は定期的にCSV出力を推奨します。
- 混用可否・混和順序は必ず各薬剤のラベル・メーカー指示を優先してください。
